# ADR-0007：按能力注册和路由数据源

## 背景

不同数据源只在部分市场、资产类型、周期或接口上可靠。把某个 Provider 整体标记为“支持”会让一个接口的成功掩盖其他接口的失败，也会让业务层依赖来源专有能力。Day 0 的真实探针已证明来源级布尔状态不足以表达认证、权限、频率、字段和网络差异。

## 决定

Provider Contract v2 按独立能力注册和路由。能力至少由来源、操作、市场、资产类型、周期/数据类别和必要权限标识；每项能力分别记录 `PASS`、`FAILED`、`UNSUPPORTED` 或 `BLOCKED`、探测时间、参数范围、限制与证据。

业务请求先声明所需能力，再由路由器从实际通过且适用于该请求的候选能力中选择。历史行情、日线校验、分钟行情、交易日历、基础资料、财务、指标和实时行情不得共享一个来源级开关。主备选择仍以完整行情分区为最小单位，禁止逐行静默混源。

固定候选职责为：JQData 优先验证历史行情；Tushare 优先验证日历、基础资料、财务和日频校验；AKShare 逐接口启用；BaoStock 作为免费校验源；QMT 仅在用户开通后作为个人实时行情支线。

## 替代方案

- 来源级启用开关：简单，但无法表达局部失败和权限差异，拒绝。
- 在业务代码中直接指定来源：会泄漏来源专有语义并阻碍主备路由，拒绝。
- 逐行多源填洞：破坏可追溯性和分区一致性，继续由 ADR-0005 禁止。

## 后果

- Provider 契约和能力报告需要升级，并保留旧报告迁移测试。
- 单项能力失败不抹掉同一来源其他已验证能力，但也不能扩张为来源整体成功。
- 路由结果必须保存能力证据、来源、降级原因和数据截止时间。
- 凭据缺失属于对应能力的 `BLOCKED/CONFIGURATION`，不得伪装为 `UNSUPPORTED` 或成功。
