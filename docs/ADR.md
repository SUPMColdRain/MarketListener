# 项目约束规则与 ADR 索引

本文件是所有开发 Agent 的强制入口。除非用户明确批准新的 ADR，否则实现不得偏离这些约束。`docs/adr/` 记录难以逆转的架构决策及原因，本文件负责把它们转化为执行规则。

**执行状态**：Day 0 已于 2026-08-04 停止且未封板。正式开发以 `Plan_full.md`、`STATUS.md` 和 `START_HERE.md` 为入口；`Plan.md` 中的 `D0-*` 仅保留为历史计划和验收证据。

## 一、不可绕过的项目约束

1. **只支持 Android 13+**：不开发、不测试、不保留 iOS 兼容层；客户端使用 Kotlin 与 Jetpack Compose。
2. **不把手机当服务器**：Android 端不得运行 PostgreSQL、TimescaleDB、Redis、Celery 或常驻 FastAPI。
3. **电脑或可选云主机负责数据生产**：采集、清洗、全市场聚合、全量策略扫描和回测不在手机上执行。
4. **离线签名包是正式版主路径**：数据通过系统文件选择器、USB 或局域网文件传输进入手机，不以在线后端为前置条件。
5. **个人数据与行情数据物理隔离**：行情包导入、替换、失败回滚不得修改交易历史、自选、资金记录和策略参数。
6. **数据源必须先探测再承诺**：文档中的覆盖、额度、分钟周期和稳定性都是待验证假设；代码和验收报告不得把未实测能力标记为已支持。
7. **QMT 是外部门控支线**：仅在用户开通账户后适配个人实时行情，不进入云端，也不阻塞离线正式版。
8. **数据源不得逐行混拼**：主备选择和降级以行情分区为单位，必须保留来源、抓取时间、数据版本和质量状态。
9. **K 线按交易时段聚合**：不得按自然整点粗暴聚合；期货必须区分自然日期与交易日。
10. **策略不是交易指令**：结果必须包含触发条件、观察理由和风险标签，不得只输出“买入/卖出”。
11. **Android 只解释声明式策略 DSL**：只执行 Kotlin 白名单节点；拒绝任意代码、未知节点、网络、文件访问和动态依赖。
12. **只导入本人签名的 DSL 策略包**：桌面端可用 Python 研究、扫描和回测，但 Android 不执行 Python 脚本。
13. **密钥不入库、不入包、不入日志**：聚宽账号、API Token 和签名私钥仅存在数据生产端的安全配置中。
14. **先代表样本闭环，再扩大数据量**：不得以“还在下载全市场数据”为由跳过数据契约、质量检查、手机导入和策略一致性测试。

## 三、Agent 修改权限

低成本执行 Agent 可以：

- 按 `STATUS.md` 中第一项 `READY` 任务实现代码、测试、脚本和普通说明文档；历史 `Plan.md` 的 D0 任务仅在用户明确重新授权时执行。
- 修复不改变公开契约的缺陷。
- 在质量报告中记录数据源失败、缺口和建议。

低成本执行 Agent 不可以：

- 将 Kotlin/Compose 改回 Flutter，或增加 iOS。
- 引入在线 API 服务器作为 Day 0 必需组件。
- 合并 `user.db` 与行情数据库。
- 删除能力证据、来源追踪、质量检查、包签名、回滚或策略测试向量。
- 因某个数据源失败而静默换源、伪造成功或使用模拟数据冒充真实验收。
- 修改标准标的键、行情包结构、策略包结构和交易日定义而不新增 ADR。

## 四、变更规则

满足以下任一条件时必须先新增 ADR，再修改实现：

- 改变客户端平台、数据库边界、数据交付方式或策略执行边界。
- 改变标准标的键、K 线时间语义或主备数据选择粒度。
- 允许手机动态安装依赖、执行 Python/任意代码、导入未签名 DSL 或直接持有数据源凭据。
- 引入持续付费的云服务或新的长期锁定技术。

新增 ADR 必须说明背景、决定、替代方案和后果，并由用户明确确认。普通库升级、页面样式和可逆实现细节不需要 ADR。

## 五、统一完成定义

一个任务只有同时满足以下条件才可标记完成：

- 实现内容与 `FULL-*` 任务编号一致，没有夹带架构改动。
- 自动化测试通过，并记录实际执行命令和结果摘要。
- 涉及数据源时输出真实的 `PASS`、`FAILED` 或 `UNSUPPORTED`。
- 涉及数据结构时提供迁移或明确说明“无迁移”。
- 不包含账号、Token、私钥、个人交易数据或大体积行情文件。
- 由不同于实现者的 Agent 完成代码审查，状态进入 `ACCEPTANCE`。
- 独立验收 Agent 按当前任务的验收标准复核并保存证据；只有验收角色可以将任务标为 `ACCEPTED`。
