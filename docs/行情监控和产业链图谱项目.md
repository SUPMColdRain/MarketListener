# 行情监控和产业链图谱项目

> **当前状态（2026-08-04）**：Day 0 已停止执行且未封板。正式项目以 [Plan_full.md](Plan_full.md) 为执行规范、[STATUS.md](STATUS.md) 为唯一实时状态源、[START_HERE.md](START_HERE.md) 为新任务入口；Day 0 实现和失败证据继续保留为历史基线。

## 1. 项目定位

本项目是面向个人使用的 Android 13+ 投研、行情观察与交易复盘工具，不是面向大量用户的金融 SaaS，也不是自动交易系统。

核心使用场景：

- 在休盘或碎片时间查看自选、行情、指标和策略筛选结果。
- 通过 K 线和策略解释寻找值得进一步观察的标的。
- 记录个人交易、资金变化和当时的市场状态，进行复盘和归因。
- 通过产业链图谱了解公司主营业务、产品、上下游、同行和行业地位。

策略结果只表达“候选标的、触发条件、观察理由和风险标签”，不构成投资建议、买卖指令或自动下单依据。

## 2. 已确定的核心取舍

1. 客户端只支持 Android 13+，使用 Kotlin 与 Jetpack Compose，不支持 iOS，不再采用 Flutter。
2. 数据采集和重计算不能稳定地在手机后台完成，由个人电脑或可选廉价云主机负责。
3. 正式版主路径由个人电脑生成签名离线增量包，手机通过文件选择器导入；未来云更新仍复用同一数据包协议。
4. 手机负责热数据查询、个人数据、行情展示和受支持的本地策略运行，不运行服务器数据库和常驻后端服务。
5. 数据生产端保留 Python 策略研究、扫描和回测；Android 只运行签名的声明式策略 DSL，不嵌入 Python，不执行任意代码。
6. 离线正式版不依赖 QMT；JQData、Tushare、AKShare 和 BaoStock 按能力逐项验证，QMT 仅在用户开通后作为实时支线。
7. 所有数据源覆盖结论必须由逐项运行探针验证，未验证的宣传、文档和模型结论只视为候选假设。

项目硬约束见 `ADR.md`，统一术语见 `CONTEXT.md`，可执行任务见 `Plan_full.md`，实时入口见 `STATUS.md`，开发数据流和 Agent 分工见 `项目开发和Agent分工时序图.html`。

## 3. 总体架构

本项目的准确架构名称是“数据生产端 + 版本化数据包 + Android 消费端”，而不是手机本地后端。

```text
┌──────────────── 数据生产端：个人电脑 / 可选廉价云主机 ────────────────┐
│ 数据源探针 → 采集 → Bronze 原始层 → 标准化 → Silver 标准层          │
│             → 质量检查 → K 线聚合 → 全市场策略扫描                   │
│             → 生成签名行情包 / 声明式策略 DSL 包                      │
└──────────────────────────┬──────────────────────────────────────────┘
                           │ 正式主路径：离线文件
                           │ 未来：对象存储下载
┌──────────────────────────▼──────────────────────────────────────────┐
│ Android 13+ 消费端                                                   │
│ 验签与原子导入 → 热行情查询 → K 线与指标 → 本地 Kotlin DSL 策略       │
│                 → 自选 → 交易历史 → 复盘 → 产业链图谱                 │
└─────────────────────────────────────────────────────────────────────┘
```

### 3.1 数据生产端职责

- 数据源登录、限流、重试和按能力独立探测与路由。
- 标的代码映射、字段标准化和数据质量检查。
- 全量历史初始化、每日增量、交易时段聚合和复权处理。
- 全市场 Python 策略扫描、历史回测和重计算。
- 生成不可变、可校验、可回滚的行情包与声明式策略 DSL 包。
- 保存本地历史数据和运行报告。

### 3.2 Android 消费端职责

- 验证并导入行情包和策略包。
- 查询热数据和按需加载冷数据分片。
- 管理自选、交易历史、资金记录、策略参数和人工确认。
- 展示 K 线、重要指标、策略结果和产业链图谱。
- 对自选或小范围标的执行本地声明式策略 DSL。
- 在无网络时保持核心查询和策略能力。

### 3.3 明确不在 Android 运行的组件

- PostgreSQL、TimescaleDB、Redis、Celery。
- 常驻 FastAPI 或其他 HTTP 后端。
- 全市场历史数据抓取、PDF 批处理和大规模回测。
- 数据源账号登录和运行时安装 Python 包。

## 4. 功能范围

### 4.1 行情监控

计划覆盖：

- A 股总市值大于 200 亿元的个股。
- 港股总市值大于 200 亿港元的个股。
- 同花顺 A 股指数。
- 去除重复跟踪指数后的 ETF。
- 国内商品指数。
- 国内期货合约、主力合约和必要的连续合约。

当前文档中的 912 只 A 股、418 只港股、1293 个指数和 532 只 ETF 都是特定日期快照，不能作为永久常量。系统必须保存筛选规则、生效日期、成员有效期和生成数据版本。

目标周期包括 15min、30min、1h、2h、4h 和 1d。最低可信周期保存在电脑端，手机只保存常用周期和近期范围，其他周期按规则生成或缓存。

用户功能包括自选、条件筛选、行业和概念联动、K 线、批量扫描结果、最近信号和异常行情提示。实时盘中提醒不属于第一阶段承诺。

### 4.2 重要指标

候选指标包括：

- A 股上涨/下跌家数、涨停/跌停家数、连板高度。
- 涨停今日接盘收益率、A 股交易总额。
- 北向资金、南向资金。
- 金银比、金油比。
- 全球资产市值排行、全球主要指数排名。
- 财新制造业 PMI。
- 中国和美国 10 年期国债收益率。
- 美元指数及其他自定义宏观、资金和情绪指标。

每个指标必须单独定义代码、口径、单位、频率、时区、来源、数据截止时间和缺失处理。金银比、金油比等计算指标必须记录输入指标版本和计算公式版本。

### 4.3 策略筛选与解释

电脑端可运行 Python 策略，负责全市场批量扫描、历史回测和 DSL 参考解释。Android 只通过 Kotlin 解释器运行签名的声明式策略 DSL，主要用于自选或小范围即时重算；Python 策略只有转换为受支持 DSL 后才能在手机运行。

每次策略运行记录：

- 策略 ID、名称和版本。
- 参数及参数版本。
- 数据包和数据分区版本。
- 价格模式与输入字段。
- 运行环境、开始/结束时间和状态。
- 候选标的、触发条件、观察理由和风险标签。

桌面 DSL 参考解释器和 Android Kotlin 解释器对同一策略包提供共享测试向量和结果一致性测试。策略失败、超时或输入不足时必须返回明确状态，不能把“无结果”和“运行失败”混为一谈。

### 4.4 交易历史与复盘

个人数据包括期初资金、出入金、成交记录、费用、持仓、策略归属和人工备注。统计包括净利润、胜率、盈亏比、最大回撤、资金曲线、持仓暴露、交易频率以及按市场、行业、策略和时间区间的归因。

交易记录和行情包分库存储。行情包升级、删除或回滚不能影响交易数据；个人数据提供独立加密导出和恢复流程。

### 4.5 产业链图谱

图谱用于快速建立产业认知，不建设论文级证据库。主要回答公司主营业务、核心产品、上下游、竞争关系、龙头地位和业务相关性强弱。

候选来源包括产业研报 PDF、年报和公告、公开网站、现有 Excel、`中国企业产业链深度图谱全集.html` 和企业市值表格。至少保留来源文件名、来源类型、更新时间、AI 置信度和人工确认状态。

产业链图谱的领域模型可在工程基线后独立固化；导入、消歧、人工审核和 Android 查询按 `FULL-700`–`FULL-704` 的依赖推进，不得阻塞真实行情主链。

2026-08-09 已落地的生产化实现（`Plan_full.md` 5.8 补充）：`行业产业链研报/`（720+ 篇，不纳入 Git）经 `reports process` 幂等解析为带状态标识的 `report_*.json`，`reports verify` 写入脚本化核验结论，`reports chains` 聚合为产业链索引并生成自包含 `industry-map.html`（SVG 图谱：原材料/上游/中游/下游/产品/服务/公司节点，支持搜索、筛选与事实定位）。图谱快照同步 `data_control/industry/industry-map.html` 并随同步包下发；Android 产业链页加载该网页快照，不重读研报。

## 5. 技术栈

### 5.1 电脑端

| 领域 | 技术 | 用途 |
|---|---|---|
| 语言 | Python 3.11 | 数据源适配、清洗、聚合、扫描和打包 |
| 校验 | Pydantic + JSON Schema | 电脑与 Android 共享契约 |
| 表格处理 | pandas / PyArrow | 接收数据源结果并写入标准列式数据 |
| 数据查询 | DuckDB | 查询 Parquet、质量分析和包构建 |
| 历史存储 | Parquet 分区 | 按市场、资产类型、周期和年份保存 |
| 包数据库 | Python sqlite3 | 生成 Android 可导入的只读 SQLite |
| 测试 | pytest | Provider、聚合、质量和打包测试 |
| 调度 | Windows 任务计划程序 | 每晚运行；云端未来可换 cron/systemd |

### 5.2 Android 端

| 领域 | 技术 | 用途 |
|---|---|---|
| 语言与 UI | Kotlin + Jetpack Compose | Android 13+ 原生应用 |
| 本地数据库 | Room + SQLite | 个人数据与热行情查询 |
| 后台工作 | WorkManager | 导入后索引、清理和可恢复轻任务 |
| 文件导入 | Storage Access Framework | 用户选择行情包、策略包和备份文件 |
| 密钥 | Android Keystore | 保护个人数据库密钥和验签配置 |
| 策略 | Kotlin 声明式 DSL 解释器 | 运行签名白名单策略节点，拒绝任意代码、网络和文件访问 |
| K 线 | 本地 Lightweight Charts + WebView | 断网可用的专业 K 线展示 |
| 测试 | JUnit、Room 测试、Compose UI 测试 | 单元、数据库和交互验证 |

Android 构建使用 JDK 21 LTS，具体 Kotlin、Gradle、AGP、Room 和策略 DSL Schema 版本必须在项目依赖锁或契约中固定，不使用无上限的动态版本。

## 6. 数据源策略

### 6.1 正式候选源与职责

| 来源 | 候选职责 | 正式处理方式 |
|---|---|---|
| JQData | 历史 A 股、ETF、指数和期货行情优先候选 | 执行真实登录、额度、日线、分钟线和资产类型探针 |
| Tushare | 交易日历、基础资料、财务和日频校验 | 每个接口独立报告权限、积分、频率和覆盖 |
| BaoStock | A 股日线、复权和免费交叉校验 | 网络可达时与主源做重叠样本对比；不可达不阻塞主链 |
| AKShare | 快照、日历、资金、宏观等辅助能力 | 逐接口探测和启用；一个接口成功不代表整源成功 |
| QMT | 未来个人实时行情 | 账户开通后的门控支线，不进入云端 |
| 手工录入 | 低频且缺少稳定接口的指标 | 建立录入与校验页面后启用 |

不得使用“主力源已定稿”这类措辞掩盖尚未实测的额度、许可证或覆盖。每次探测生成包含时间、依赖版本、样本、行数、周期、历史深度、耗时和错误分类的能力报告。

### 6.2 Provider 契约

所有来源实现 Provider Contract v2。请求参数化并声明所需操作、市场、资产类型、周期或数据类别；每项能力独立注册状态、权限、限制和证据：

```text
probe_capabilities()
fetch_instruments(market, asset_type)
fetch_bars(source_symbol, period, start, end)
fetch_indicators(indicator_code, start, end)
fetch_calendar(market, start, end)
health_check()
```

Provider 输出的是来源观测，不是直接供 UI 使用的标准行情。一个能力成功不能推断同一来源的其他能力成功；只有完成标准化、质量检查、能力路由和分区选择后才能进入 Silver 层与行情包。

### 6.3 主备与冲突规则

- 为每个“市场 + 资产类型 + 周期”配置主源和备源。
- 主源分区完整且质量通过时，整分区采用主源。
- 主源失败时才选择质量通过的备源分区，并记录降级原因。
- 不允许把两个来源在同一分区内逐行填洞，除非以后新增 ADR 定义明确的合并算法。
- 跨源差异超过阈值时进入隔离区，不自动选择“看起来更合理”的值。
- 必须检查来源许可和个人使用限制，不把原始数据包公开分发。

## 7. 标准数据模型

### 7.1 标准标的

标准标的键由 `country_or_market`、`exchange`、`asset_type` 和 `code` 构成，例如：

```text
CN:XSHG:EQUITY:600519
CN:XSHE:ETF:159915
HK:XHKG:EQUITY:00700
```

期货合约、主力连续和指数连续必须使用不同资产类型，不把会换月的“主力”当成固定合约。

标的目录至少包含名称、交易所、资产类型、上市/到期时间、状态、币种、价格单位、来源映射和更新时间。

### 7.2 标的范围

`universe_definition` 保存筛选规则、币种、阈值和版本；`universe_membership` 保存成员、生效开始、失效时间和用于筛选的数据日期。回测必须使用当时有效的范围，不能使用今天筛出的股票回测过去。

### 7.3 K 线

标准 K 线至少包含：

- 标准标的键、周期和交易日。
- bar 开始时间、结束时间和时区。
- open、high、low、close、volume、amount、open_interest。
- 不复权/前复权/后复权模式。
- 来源、来源周期、抓取时间、数据版本和质量状态。
- 聚合规则版本及是否为尾部不足整周期的 bar。

保存不复权行情和独立复权因子。策略显式声明价格模式，避免不同来源和回测环境默认复权方式不同。

### 7.4 交易时段聚合

聚合使用交易所日历和品种交易时段，标准 OHLCV 规则不变，但分组边界不能使用自然整点：

- A 股处理午休和完整交易日。
- 港股处理其独立交易时段及尾部 bar。
- 期货区分日盘、夜盘、跨午夜和交易日归属。
- 2h、4h 允许出现由规则定义的尾部不足周期 bar，并明确标记。

原始最低周期长期保存在电脑端。Android 不永久存储所有派生周期：常用结果进入热库，其他结果按需计算或从冷数据分片加载。

## 8. 电脑端存储与每日更新

### 8.1 数据分层

```text
Bronze：来源响应或规范化快照，用于追查字段变化
Silver：标准标的、标准 K 线、指标、日历和质量状态
Gold：策略信号、Android 行情包和统计结果
```

Silver 使用 Parquet 按市场、资产类型、周期和年份分区，DuckDB 管理查询视图、任务游标和质量报告。每个任务必须幂等，重复运行不产生重复数据。

### 8.2 更新时间语义

不能只保存“今晚更新成功”。每个行情分区单独保存数据截止时间：

- A 股和港股可在收盘后生成完整日内分区。
- 国内期货夜盘可能属于下一个交易日，晚上更新只能标记为部分数据或延后封板。
- 指标按自己的日度、周度或月度频率保存截止时间。

数据包允许部分市场成功，但 Android 必须显示每个分区的截止时间和缺口。

### 8.3 可选廉价云主机

当电脑手工更新影响使用时，可把同一个 Python CLI 和锁定依赖部署到廉价云主机，通过定时任务生成行情包并上传对象存储。Android 下载静态清单和数据包即可，不新增在线查询后端。

云方案必须先估算数据源授权、出口网络、磁盘、运行时间和对象存储流量；凭据放在云平台 Secret 或受限环境变量中。

## 9. 行情包

行情包是不可变发布物，至少包含：

```text
market-package.zip
  ├─ manifest.json
  ├─ payload.sqlite
  ├─ quality-report.json
  └─ signature.ed25519
```

`manifest.json` 至少记录包 ID、Schema 版本、生成时间、最低 App 版本、每个分区的数据截止时间、来源运行状态、文件大小、行数和 SHA-256。

Android 导入顺序：

1. 通过系统文件选择器获得只读文件。
2. 验证签名、哈希、Schema、最低 App 版本和剩余空间。
3. 解包到应用私有暂存目录。
4. 检查数据库完整性、行数、唯一键和外键。
5. 原子切换活动行情版本。
6. 保留最近一个正常版本供回滚。
7. 最后再由 WorkManager 重建非关键索引和缓存。

任何失败都不得删除当前正常版本，也不得修改个人数据库。

## 10. Android 数据边界

### 10.1 `user.db`

保存自选、交易记录、资金流水、策略配置、人工备注、图谱人工确认和导入历史。这些数据不可从行情源重建，必须独立加密备份。

### 10.2 `market_hot.db`

保存近期标准行情、指标、电脑端信号、标的目录和质量信息。它是版本化可重建数据，可以原子替换和回滚。

### 10.3 冷数据分片

保存完整日线和较长历史分钟数据，按市场、周期和年份拆分，只读加载。实际保留年限在全量数据体积实测后确定，不在架构阶段拍脑袋承诺。

## 11. 声明式策略 DSL 包

策略包结构：

```text
strategy-package.zip
  ├─ manifest.json
  ├─ strategy.json
  ├─ default-params.json
  ├─ test-vectors.json
  └─ signature.ed25519
```

`strategy.json` 由版本化 JSON Schema 约束，只能包含已登记的输入、参数、指标、运算符、条件组合和信号输出。Kotlin 解释器拒绝未知节点、任意代码、网络、文件访问和动态依赖，并具备超时、取消、错误捕获和输出限制。

策略包必须由电脑端私钥签名，Android 只内置公钥。桌面 Python 可用于研究、批量扫描、回测和 DSL 参考解释，但不会随策略包进入 Android。两端使用共享测试向量验证离散结果一致和明确的浮点误差阈值。

## 13. 数据安全、隐私和备份

- 数据源凭据和签名私钥只存在电脑或云生产端，不进入 Git。
- 日志统一遮盖用户名、Token、请求签名和敏感路径。
- 个人数据使用 Android 应用沙箱和 Keystore 保护的密钥。
- 个人数据导出使用独立加密备份格式，不夹带大体积行情。
- 行情包只用于个人设备，不公开再分发来源数据。
- App 卸载可能删除应用私有数据，交易记录模块上线前必须完成备份与恢复验收。

## 14. Agent 分工与治理

### 14.1 用户

- 决定业务范围、策略含义和最终取舍。
- 提供聚宽等账号，但不把凭据发给文档或代码仓库。
- 在真机执行需要登录、文件授权或人工判断的验收步骤。
- 批准新增或修改 ADR。

### 14.2 低成本执行模型

Day 0 历史上曾按 `Plan.md` 的单个任务编号执行开发和测试；该队列已停止。正式开发按 `Plan_full.md` 的 `FULL-*` 单项任务工作，由 `STATUS.md` 维护唯一实时状态，实现、审查和验收必须分离。

### 14.3 审查与验收模型

代码审查必须由不同会话或不同 Agent 完成，优先发现数据错误、时间语义、隐私、安全、失败处理和测试缺口。验收 Agent 必须实际运行测试或操作真机，不接受纯文字判断。

### 14.4 升级处理

出现以下情况时交回用户或高推理模型：

- 数据源许可、覆盖或成本导致整体路线变化。
- 策略 DSL 表达力或两端一致性无法满足业务策略要求。
- 需要改变标准标的键、交易日语义或数据包 Schema。
- 需要引入常驻云服务、在线账户体系或自动交易。
- 产业链实体模型出现无法通过现有术语解决的歧义。

## 16. 主要风险与应对

**数据源突然失效**：按能力注册与路由、真实探针、分区级主备和能力报告。

**免费额度不足**：先测代表样本与真实调用量，再决定缩短分钟历史、分批更新或使用应急预算。

**K 线时间错误**：交易时段规则版本化，并用 A 股午休、港股尾部 bar 和期货夜盘固定样本测试。

**手机存储膨胀**：电脑保存全量最低周期，手机采用热库、冷分片和按需周期缓存。

**行情更新损坏交易记录**：个人库与行情库物理隔离，行情包暂存验证后原子切换。

**移动策略不兼容或表达力不足**：使用版本化声明式 DSL、Kotlin 白名单解释器和跨端共享测试向量；新增节点必须同时升级 Schema 与两端解释器。

**低成本 Agent 擅自改架构**：强制阅读 ADR、单任务交付、独立审查和运行验收。

**云成本失控**：云端只运行批处理与静态包发布，先度量再购买，不预建在线后端。

## 17. 一句话总结

项目以“数据生产端 + 版本化数据包 + Android 消费端”为核心，逐步实现行情观察、策略结果、交易复盘和产业链图谱；正式任务从 `START_HERE.md` 与 `STATUS.md` 启动，计划固化前的历史基线和未验证能力保留在 `docs/正式开发交接.md`。
